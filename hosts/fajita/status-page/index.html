01How the devices combine

Assign each device its job and the whole need-set is covered — then shrink the fallback set over time by shipping native apps and bridges.

OnePlus · NixOS

Daily driver

Native apps we built + a few PWAs. Fully declarative, yours, hackable — the actual project.

  • Comms, notes, media, finance now native or on-device
  • Official-only chat runs in Waydroid on-demand
  • 30 / 32 use cases live here

iPhone · iOS

In-bag fallback

Stays in the bag. Handles only what Linux can't — zero maintenance.

  • Garmin watch sync (no Linux client)
  • Camera when the shot matters
  • Official-only banking · WhatsApp calls

Pixel · GrapheneOS

Not chosen

The full-native alternative if the Nix experiment is ever abandoned.

  • Covers everything natively
  • Better privacy than iOS
  • …but another OS to maintain, and not the project
The play: daily-drive OnePlus/Nix; close holdouts one by one. The note/media/finance clients are now shipped as our own native apps, and official-only chat (WhatsApp/Slack/Discord) runs in Waydroid on-demand — so the iPhone is down to just Garmin watch sync and a couple of official-only banking apps.

04Decisions & config

Smaller calls that don't need a build — research-backed.

VPN on cellular

config

Skip the Windscribe client: generate a WireGuard config (account → Config Generator) → networking.wg-quick with mtu = 1280 + persistentKeepalive = 25 (the cellular gotchas) + AllowedIPs = 0.0.0.0/0 (auto kill-switch). Windscribe already ships arm64 debs, so a real aarch64 client is a trivial flake fix later.

PWA icons

polish

Vendor icon files in the repo → install into the hicolor theme (hicolor/512x512/apps/pwa-<id>.png) → Icon = "pwa-<id>", wrapped with symlinkJoin. Prior art: nix-chromium-webapps. Self-hosted apps have manifest icons; brands from dashboardicons.com (full-color, not simple-icons glyphs).

Stocks

shipped

Turned out no maintained native GTK4 stocks app was both phone-adaptive and in nixpkgs — so we built our own. Bourse (from-scratch GTK4/libadwaita, Yahoo unofficial API, no key) replaced the Yahoo PWA: watchlist, markets/futures strip, drag-reorder, after-hours, fundamentals. See §03.

Matrix client

decided

Fractal for Matrix — the only GTK4/libadwaita client with real E2EE (cross-signing + verification via matrix-rust-sdk). Chatty stays for SMS/MMS only (its Matrix is experimental, decrypt failures). Caveats: Fractal has no background notifications and no Matrix calls.

05Waydroid — Android container, on-demand

We adopted Waydroid on-demand for the three official-only chat apps — WhatsApp, Slack and Discord — each running as its own official Android app in a single GNOME window. Here's the setup and the tradeoffs we accepted. Checkpoints 1–6 (kernel, module, DPI, single-window, notification forwarding, close-to-quit) are done; APK-provisioning and the battery A/B remain.

Overall viabilitySDM845 · GNOME Mobile · NixOS

in use

Waydroid is a real, maintained project that runs a full Android (LineageOS) system inside an LXC container on the host Linux kernel — no emulation, native aarch64. On a phone it works but is not seamless. The problems are specific: push notifications are broken without Google services, Waydroid blocks suspend (killing battery unless you stop the session when not in use), Bluetooth passthrough does not exist (so Garmin sync is impossible), and Play Integrity fails entirely (banking, Garmin Connect).

On aarch64 hardware like the 6T you use the ARM image natively — no x86 translation layer needed, which is a genuine advantage over desktop setups. Freedreno (the open Mesa driver for Adreno) can provide GPU acceleration inside the container; the SDM845's Adreno 630 is supported by Freedreno in the host, but container-side GPU passthrough for older Adreno requires extra setup and is not guaranteed out of the box.

Bottom line: It is in use here — WhatsApp, Slack and Discord run as official Android apps, one GNOME window each, on-demand. A GNOME Shell "close-to-quit" extension force-stops an app on swipe-up-close and stops the whole session ~30s after the last window closes, which contains the battery cost. Config lives in hosts/fajita/waydroid.nix + waydroid-watcher/. Still not a background notification sink, and still doesn't cover Garmin or banking — the iPhone keeps those.

Kernel & setup requirements

non-trivial

The host kernel needs: CONFIG_ANDROID_BINDER_IPC, CONFIG_ANDROID_BINDERFS, CONFIG_PSI=y. Ashmem is no longer required (replaced by memfd since waydroid 1.2.1 / kernel 5.18+). The SDM845 kernel in postmarketOS (linux-postmarketos-qcom-sdm845, now on 7.1) tracks mainline closely enough that binder and PSI are likely present, but you need to verify — waydroid checkconfig will tell you what is missing.

NixOS has a first-party module: virtualisation.waydroid.enable = true. On kernels 6.17+ use virtualisation.waydroid.package = pkgs.waydroid-nftables (merged in nixpkgs late 2025). mobile-nixos does not expose this module by default — you would wire it in manually the same way you hand-rolled linux-builder. The module sets up the LXC images, a systemd unit, and binder kernel modules. One documented gotcha: running nixos-generate-config after enabling Waydroid can write spurious fstab entries; generate config first.

Wayland session is required — GNOME Mobile on Mutter satisfies this. On Phosh or GNOME, also comment out load-module module-suspend-on-idle in PulseAudio config; otherwise the audio server can crash the Waydroid session randomly.

Setup effort: moderate on a stock NixOS desktop, higher on mobile-nixos since you need to confirm the device kernel has binder built in and wire the module outside the normal mobile-nixos module tree.

Push notifications — the real problem

broken by default

Waydroid ships a de-googled LineageOS image. Without Google Play Services, apps that rely on FCM (Slack, WhatsApp, Discord) get zero push notifications — the app has to be in the foreground. microG is the partial fix: it re-implements the FCM endpoint and can forward push to the apps, but it is fragile.

Waydroid 1.6.0 (November 2025) added D-Bus notification forwarding from Android to the Linux desktop — so notifications that arrive inside the container can bubble up to GNOME Shell. This is real and useful when microG is working. The catch: the UbuntuHandbook reviewer found the feature "seems not working" with the default LineageOS image out of the box. The companion Python package gbinder-python >= 1.3.0 is required or the session manager crashes on picture notifications.

The deeper problem: microG's FCM stack has a known regression (issue #2896, May 2025) where updating to microG 0.3.7.250932 breaks push for WhatsApp and others, with "cloud messaging: disconnected" in diagnostics. No confirmed fix as of July 2026. Even when microG works, the Android container must stay running in the background for notifications to arrive — which conflicts badly with the suspend/battery issue below.

Bottom line on notifications: broken out of the box, partially fixable with microG, currently regressed in microG 0.3.7, and fundamentally in tension with mobile power management. This is exactly why we run Waydroid on-demand, not in the background — you open WhatsApp/Slack/Discord when you want them; we don't rely on reliable background push from the container.

Battery & suspend

significant

This is the hardest problem for mobile use. When the Waydroid session is active, it holds a wakelock that prevents the phone from entering deep suspend. In practice: screen can wake every 5-10 minutes on its own, battery drains fast. One PinePhone report saw a drop from 75% to 61% in minutes just from the container running. The Librem 5 (3 GB RAM) hits memory pressure immediately — Android starts killing foreground apps when ZRAM fills, which is the baseline condition on a 6 GB 6T once you have Linux apps + the Android container loaded.

Known workarounds: waydroid prop set persist.waydroid.suspend false turns off container-internal suspend but does not fix the host wakelock. The practical approach everyone lands on: stop the Waydroid session when not actively using it (waydroid session stop or a helper script), start it when you need an Android app, stop it after. This is exactly the on-demand model we adopted — our waydroid-watcher force-stops the app on swipe-up-close and stops the whole session ~30s after the last window closes, so the wakelock is only held while you're actively using a chat app.

RAM baseline: an idle Android container uses roughly 600-900 MB on top of everything else. On the 6T (6 GB RAM) this is workable if you are not running many other things, but you will feel it.

DPI / scaling on a phone screen

solvable

Waydroid defaults to a tablet-style layout at whatever DPI the host reports. For a phone screen you need to set the DPI and resolution explicitly: waydroid prop set persist.sf.lcd_density 420 (or similar for the 6T's ~402 ppi screen) and make sure the container sees the correct display dimensions. Without this, apps render at desktop scale and are unusable as phone apps — tiny tap targets, text overflowing, etc.

Single-window mode (the default in Waydroid) runs one Android app fullscreen, which maps well to a phone. Multi-window mode requires enabling freeform windows in Android Developer Options and works better on a tablet form factor. For phone use, stick with single-window.

Per-app verdicts

adopted

Slack — The Android app runs and is far better than the desktop-scaled PWA, so this is now running here via Waydroid on-demand. The one caveat is notifications: Slack relies on FCM push, which is unreliable inside the container — so we treat it as an app you open, not a background push sink. Live: official Slack, on-demand.

WhatsApp — Now running here via Waydroid on-demand. The Android version makes and receives real voice/video calls (the web version can't — the genuine win over the old PWA); the app is companion-linked to the iPhone number. Notifications via microG are unreliable, so it's a "open it to call/chat" workflow, which the close-to-quit watcher handles cleanly. Live: official WhatsApp, on-demand.

Discord — Now running here via Waydroid on-demand. The Android app works well for chat; there is a known issue where Discord doesn't reliably register for FCM push even with microG (GmsCore #540), so notifications aren't dependable — again fine for an app you open when you want it. Live: official Discord, on-demand.

Garmin Connect — Two blockers, both fatal. First: Bluetooth passthrough does not exist in Waydroid — the Android container has no access to the host Bluetooth adapter, so watch sync (the whole reason for the app) is impossible. Second: Garmin Connect requires at minimum Device Integrity in Play Integrity API; Waydroid cannot pass even Basic Integrity without additional hacks, and those hacks are fragile. Even on GrapheneOS (a hardened real Android), Garmin Connect has active Play Integrity problems. Waydroid cannot replace iPhone for Garmin. iPhone stays.

Summary: Waydroid is adopted on-demand for WhatsApp, Slack and Discord — official Android apps, one GNOME window each, force-stopped on close so the battery cost is bounded. Garmin stays on the iPhone (Bluetooth + Play Integrity are still fatal), and the container remains a poor fit for background push — which is exactly why we run it on-demand.
